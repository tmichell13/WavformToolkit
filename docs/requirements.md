# Requirements - Waveform Analysis Toolkit

## 1. Overview/Purpose
What is this and why does it exist?

## 2. Users/Stakeholders
Who uses this, and why do they need it?

## 3. Scope
What are we building, and what are we not building? What are the boundaries of the system?

## 4. Functional Requirements
What must the system do? What are the specific features and capabilities that the system must have?
Written as user stories or "shall" statements, each with an ID and acceptance criteria.

## 5. Non-Functional Requirements
How well must it do it? Accuracy performance, portablility, maintainablility.

## 6. Data/Interface Requirements
Input/output formats, data sources, and any external systems the system must interface with.

## 7. Constraints
Fixed decisisions: language, framework, timebox, budget, etc.

## 8. Assumptions & Dependencies
Things we assume to be true, and external factors that the system depends on.

## 9. Priority
What is most important to deliver first, and what can be deferred or dropped if necessary?
Must/Should/Could/Won't(MoSCoW) prioritization.

## 10. Traceablility
Which test proves each requirement? How do we know we have met the requirements?

## 11. Glossary
Domain terms

## 12. Open questions
Things that are still unclear and need to be resolved before development can proceed.
